3. Shared Template & Global CSS

HTML Structure

The base template uses a standard semantic structure with <header>, <nav>, <main>, and <footer> elements. The <header> contains the site logo and navigation bar; the <main> is a placeholder for each student's unique page content; the <footer> contains site-wide links, student details, and accessibility information.

The template includes detailed HTML comments explaining which sections must not be modified, and how other students should integrate their content. This was essential for maintaining consistency across four independently developed pages.

CSS Techniques

The global CSS is structured into numbered sections covering: CSS custom properties (variables), reset and base styles, typography, layout containers, header, navigation, main, footer, cards, buttons, section headings, hero banners, and utility classes.

  • CSS custom properties: All colours, fonts, spacing, radii, and shadows are defined as variables under :root, allowing the entire visual theme to be adjusted from one location.
  • Flexbox: Used in the header inner container, navigation list, footer inner, and card layouts for reliable cross-browser alignment.
  • CSS Grid: The .card-grid and .footer-inner use grid-template-columns: repeat(auto-fit, minmax(...)) for responsive multi-column layouts without media queries.
  • Transitions: All interactive elements (links, buttons, cards, nav items) use CSS transitions for smooth hover feedback.
  • Sticky header: The header uses position: sticky; top: 0; z-index: 1000 to remain visible as users scroll.

Design Rationale

The colour palette was chosen to align with SDG 13's official identity — deep forest greens convey nature and urgency, while the warm amber accent provides visual contrast for interactive elements without straying from an earthy, credible aesthetic. The Playfair Display / Source Sans 3 pairing was chosen to balance editorial gravitas (serif headings) with high legibility at small sizes (sans-serif body text).

The card component is central to the design system, providing a reusable, consistently styled container for SDG-related content across all pages. The .btn class system supports both primary (filled) and secondary (outlined) states, ensuring clear visual hierarchy on CTAs.

4. Home Page

HTML Structure

The Home Page is divided into four distinct content areas within <main>: a hero banner (<section> with class="home-hero"), a statistics strip, the mission cards section, and an interactive content gallery. All sections use semantic HTML elements with appropriate aria-label and aria-labelledby attributes to support screen readers.

Each mission card is wrapped in an <article> element, reflecting that each card represents a standalone piece of content that could make sense in isolation — appropriate per the HTML specification for this element.

CSS Techniques

The Home Page uses embedded CSS within a <style> block for all page-specific rules. These include:

  • Hero background: A CSS linear-gradient() overlay on top of a background image creates a legible, atmospheric banner without JavaScript.
  • Statistics strip: CSS Flexbox with flex-wrap: wrap creates a responsive row of statistics that stacks gracefully on small screens.
  • Gallery tiles: position: relative on the tile container and position: absolute on the overlay label implements the sliding label reveal effect using CSS transitions on transform and opacity.
  • Hover animation: The .gallery-tile:hover img rule applies a subtle scale(1.02) and opacity change, reinforcing interactivity.

A minimum of fifteen CSS rules are defined in the embedded style block, each clearly commented with its purpose.

5. Gallery Page

HTML Structure

The gallery grid uses a <div> with role="list" containing six .thumb-wrap elements each with role="listitem" and tabindex="0". This makes the gallery keyboard-navigable and screen-reader accessible without requiring an actual <ul> (which would conflict with the visual grid layout).

The modal dialog is implemented as a fixed-position <div> with role="dialog", aria-modal="true", and aria-labelledby="modal-title", following ARIA best practices for modal patterns.

JavaScript

All interactivity is handled by JavaScript using addEventListener — no CSS-only tricks are used for the core interaction logic:

  • Hover: mouseenter and mouseleave event listeners add/remove the .hovered class, which triggers CSS transitions for visual feedback.
  • Click to expand: A click listener calls openModal(id), which uses the galleryData array to look up the correct image, alt text, title, and description, then populates the modal DOM elements and displays the modal.
  • Close: Three closing mechanisms: close button click, backdrop click (checking e.target === backdrop), and Escape key listener on the document.
  • User customisation: Colour buttons apply style.color and style.background to the #modal-content-area element. Font buttons apply style.fontFamily. Both use querySelectorAll and forEach, with a .selected class to highlight the active choice.
  • Keyboard access: A keydown listener on each thumbnail triggers openModal on Enter or Space.

CSS Techniques

Page-specific CSS is embedded in a <style> block. Notable techniques include CSS @keyframes modalIn for the modal entrance animation, CSS Grid for the thumbnail grid, and CSS position: absolute with gradient backgrounds for the overlay labels.

6. Content Page — Climate Science Explained

HTML Structure

The content page uses a two-column CSS Grid layout: a sticky side navigation (<aside>) and a main article (<article>). The article is divided into six <section> elements, each with a unique id attribute matching the anchor links in the side navigation. Heading hierarchy is strictly maintained: one <h1> for the page title, <h2> for section titles, and <h3> for sub-sections within sections.

Internal anchor links use the pattern href="#section-id", with scroll-behavior: smooth set on html in the global CSS to produce smooth scrolling. Each anchor target has a matching id on its <section> element.

CSS Techniques

  • CSS Grid: The .content-layout uses grid-template-columns: 220px 1fr to create the sidebar and main content columns.
  • Sticky sidebar: position: sticky; top: 90px keeps the navigation alongside the content as the user scrolls.
  • Go to Top button: Implemented with position: fixed; bottom: 2rem; right: 2rem and a simple href="#top" anchor — no JavaScript required.
  • Image styling: Article images use a fixed height with object-fit: cover, a border-radius, and a CSS box-shadow for a polished, consistent appearance.
  • Highlight boxes: CSS linear-gradient backgrounds on .highlight-box create visually prominent callout sections.

Content

The content covers six areas of climate science: the definition of climate change, the greenhouse effect and key greenhouse gases, observed evidence of change, global impacts, climate tipping points, and individual actions. All content is original and written by the student — it does not reproduce text from the UN website or any other source verbatim.

7. Challenges & Lessons Learned

Challenge 1: Creating a Reusable Template Others Could Follow

The most significant challenge was designing the HTML template and global CSS in a way that was flexible enough for four different page types, yet strict enough that teammates could not accidentally break the shared structure. My solution was to add extensive HTML and CSS comments clearly marking which sections must not be modified, and to use CSS custom properties (var()) so that teammates could reference the colour palette without needing to know the specific hex values.

Challenge 2: JavaScript Modal Accessibility

Making the gallery modal fully accessible — including focus trapping and keyboard navigation — was more complex than anticipated. I learned about ARIA roles (role="dialog", aria-modal) and the importance of moving focus to the close button when the modal opens. I also added an Escape key listener and a click-outside handler to provide multiple intuitive closing mechanisms.

Challenge 3: Responsive Layout Without Conflicts

Ensuring that page-specific embedded CSS did not conflict with the global CSS required careful naming conventions and scoping. I resolved this by using highly specific class names for page-specific elements (e.g. .home-hero, .content-layout) that could not clash with global class names.

Lessons Learned

This project reinforced the value of designing a design system before writing any page content. The time invested in the global CSS and template saved significant development time overall and produced a more cohesive result. I also learned that accessibility is not an afterthought — it requires architectural decisions from the very start of development.

8. Accessibility Considerations

Semantic HTML

All pages use appropriate semantic elements: <header>, <nav>, <main>, <footer>, <article>, <section>, and <aside>. This gives screen readers meaningful structural information about the page, improving navigation for visually impaired users.

Alternative Text

Every image on every page I implemented includes a descriptive alt attribute. These are not generic labels ("photo of trees") but meaningful descriptions of what the image shows and why it is relevant to the content (e.g. "Vast Arctic ice sheet with large cracks and melt pools under an orange twilight sky"). The site logo also includes alt text.

Keyboard Navigation

Gallery thumbnails include tabindex="0" and respond to both Enter and Space key events, mirroring native button behaviour. The modal receives focus on open and can be dismissed with Escape. Nav links are fully keyboard-navigable and have visible :focus-visible outlines defined in the global CSS.

Colour Contrast

The colour palette was designed with contrast in mind. White text on the dark forest green header (#1B4332) exceeds WCAG AA contrast requirements. Body text (#1C1C1C) on the off-white background (#F8F5F0) also meets WCAG AA standards.

ARIA Attributes

aria-label is used on the site logo link, nav element, and Go-to-Top button. The modal uses role="dialog", aria-modal="true", and aria-labelledby pointing to the modal title. The gallery grid uses role="list" and role="listitem" to provide list semantics without requiring a <ul>.
